# 帧浏览、标注状态与渲染修复设计

## 目标

在现有单帧点云与全局点云 6DOF 配准工具中完成以下改进：

1. 修复高坐标点云加载后 3D 视图看不到点云的问题。
2. 保证 X-Z、Y-Z、Diag +45°、Diag -45° 四个剖面使用一致、可靠的刷新和范围计算。
3. 根据 YAML 输出目录中的同名文件显示当前帧“已标注/未标注”。
4. 扫描单帧点云目录，支持手动输入、下拉选择、上一帧/下一帧浏览，并显示 `已标注数/总量`。
5. 将路径与输出面板移动到主窗口右下角，与 6DOF 控件和矩阵信息组成右侧栏。

原脚本 `src/frame_register_manual.py` 保持不变。浏览选帧只更新 Frame ID，不自动加载点云；用户仍需点击“加载当前帧”。

## 已验证的问题现状

真实样本：

- 全局地图：`D:/1_data/map_seg/global_map/jinhua/colored_map_global_voxel_blue_filled.pcd`
- 单帧点云：`D:/1_data/map_seg/global_map/jinhua/velodyne_map/1781158324500077000.pcd`
- 初始 LiDAR 原点：约 `(8628.86, 9650.01, 106.995)`

3D 场景相机中心在加载后仍为 `(0, 0, 0)`，而点云位于高坐标区域，因此点云落在视锥之外。真实样本的 X-Z 剖面并非空数据：当前参数下 Reference 有 3289 点，Adjusted 有 986 点。修复应分别处理相机聚焦和剖面显示范围，不能通过修改切片方向来掩盖问题。

## 架构

### FrameCatalog

新增独立的帧目录模型，负责文件系统扫描与标注统计，不让 UI 控件直接承担目录业务逻辑。

公开行为：

- 扫描给定目录第一层的 `.pcd` 文件，不递归。
- 扩展名大小写不敏感，以文件 stem 作为 Frame ID。
- 重复 stem 只保留一项。
- 纯数字 ID 按数值排序，其他 ID 使用不区分大小写的自然排序。
- 根据 YAML 输出目录中的 `<frame_id>.yaml` 判断当前帧是否已标注。
- 标注数量只统计扫描得到的 Frame ID，不统计无对应 PCD 的 YAML。
- 提供上一帧、下一帧和指定当前 Frame ID 的索引查询；到达边界时停留在边界，不循环。

目录无效或扫描失败时返回明确错误，并保留 UI 中上一次成功扫描的列表。

### DataIOPanel

Frame ID 输入改为可编辑下拉框。保留兼容属性 `frame_id_edit`，指向下拉框的行编辑器，避免破坏现有控制器和测试。面板增加：

- “刷新列表”按钮；
- “上一帧”和“下一帧”按钮；
- 当前帧“已标注/未标注”状态；
- `N/M（已标注/总量）`统计标签。

通过文件对话框选择单帧目录后自动扫描。手工修改目录文本不会反复扫描大目录，用户可点击“刷新列表”。下拉选择、上一帧和下一帧只改变 Frame ID 与标注显示，不发出加载信号。

YAML 输出目录、Frame ID 或扫描列表变化时，执行轻量文件存在性检查。成功导出 YAML 后重新计算当前状态和标注数量。

### 主窗口布局

主窗口使用左右两列：

```text
┌───────────────────────────────┬──────────────────────────┐
│                               │ 6DOF 调整                │
│          3D 视图              │                          │
│                               ├──────────────────────────┤
│                               │ 矩阵与质量信息           │
├───────────────┬───────────────┼──────────────────────────┤
│ X-Z           │ Y-Z           │ 数据、帧浏览与输出       │
├───────────────┼───────────────│ 上一帧 / Frame / 下一帧  │
│ Diag +45      │ Diag -45      │ 状态与标注统计           │
└───────────────┴───────────────┴──────────────────────────┘
```

左侧上方为 3D 视图，左侧下方为四个剖面。右侧从上到下为 6DOF 控件、矩阵与质量信息、可折叠的数据/帧浏览/输出面板。右侧栏应保持可用宽度，较小窗口下允许矩阵区域或整个右侧内容滚动，不能覆盖左侧图形。

## 渲染修复

### 3D 相机

`Scene3DView.set_reference()` 仅更新 Reference 点图元。新增显式相机聚焦接口，在新帧成功加载后以初始 LiDAR 原点 `C0` 为相机中心，观察距离由地图 ROI 半径计算。

手动 6DOF 微调、Undo/Redo、ICP 和剖面参数变化只更新图元，不重新聚焦相机，以保留用户当前视角。切换并成功加载另一帧时重新聚焦。

### 2D 剖面

四个剖面统一使用一个原子刷新接口：

1. 接收 Reference 和 Adjusted 两组 `(s, z)` 点；
2. 丢弃 NaN 和 Inf；
3. 分别更新两个独立 ScatterPlotItem；
4. X 轴固定为 `[-slice_half_length, +slice_half_length]`；
5. Y 轴基于两组有效点的联合范围显式设置，并增加小比例边距；
6. 两组均为空时清空旧点并显示“当前剖面无点”；重新出现数据时隐藏空状态。

legend 继续固定显示 Reference Map 和 Adjusted Frame，不因刷新重复创建。

## 标注状态规则

设当前规范化 Frame ID 为 `id`，YAML 输出目录为 `yaml_dir`：

```text
yaml_dir / (id + ".yaml") 存在且为文件 => 已标注
否则                              => 未标注
```

判断不读取 YAML 内容。手工输入且不在扫描列表中的 Frame ID 仍显示其文件存在状态，但不会加入总帧数或已标注数量。

成功导出后立即刷新。取消覆盖、导出失败或只发生 PCD 写入失败时，以实际 YAML 是否存在为最终显示依据。

## 数据流

1. 用户选择单帧点云目录或点击“刷新列表”。
2. FrameCatalog 扫描并排序 Frame ID。
3. DataIOPanel 更新可编辑下拉框，尽量保留当前手工输入。
4. 用户选择下拉项或上一帧/下一帧时，只更新 Frame ID 和标注状态。
5. 用户点击“加载当前帧”，现有 FrameLoader 严格读取 `<id>.pcd` 和 `<id>.txt`。
6. 加载成功后重置本帧调整状态，更新 Reference/Adjusted/Origin/四剖面，并聚焦 3D 相机。
7. 导出成功后刷新 FrameCatalog 的标注集合和 UI 统计。

路径编辑或扫描失败不得覆盖当前已加载的有效帧、位姿模型或视图。

## 错误处理

- 单帧目录不存在或不可读：显示具体目录和原因，保留上一次列表。
- 目录中没有 PCD：显示空列表和 `0/0`，手动 Frame ID 仍可输入。
- YAML 输出目录为空或无效：当前状态为“未标注”，标注计数为 `0/总量`，导出按钮维持禁用。
- Frame ID 不合法：沿用现有规范化与路径穿越保护。
- 剖面只含非有限值：按空剖面处理，不向 pyqtgraph 传入非有限坐标。
- 3D Reference 为空：不改变当前相机中心，避免产生 NaN 相机参数。

## 测试与验收

### 单元测试

- FrameCatalog 扫描、不递归、大小写扩展名、重复 stem、数字与自然排序；
- YAML 文件存在性、无关 YAML 排除、手工输入状态、标注计数；
- 上一帧/下一帧边界不循环；
- ProfileView 的有限值过滤、联合 Y 范围和空状态；
- Scene3DView 对高坐标中心的聚焦参数。

### UI 与集成测试

- 下拉选择和上一/下一帧不触发加载；
- 手工输入仍可构造 LoadRequest；
- 选择目录和刷新按钮更新列表；
- 导出成功后状态从未标注变为已标注、计数同步更新；
- 右侧栏包含 6DOF、矩阵和数据面板，左侧包含 3D 与四剖面；
- 新帧加载调用一次相机聚焦，微调不重复聚焦。
